WAF 行为分析设计：赋予防护系统跨请求的"记忆"

引言

实时防护层看的是单条请求：这个请求像不像攻击？但很多恶意行为在单请求维度上是完全正常的——分布式爬虫把请求摊到几千个 IP 上，每个 IP 每分钟只来一次；扫描器把探测动作拆到几天里慢慢做。单看任何一条请求，都无害。

行为分析层就是为解决这个问题而生的：它是离线分析系统，消费实时防护层写入的访问日志，跨请求、跨时间窗口分析访问模式，将分析结论（封禁规则、风险标记）写入规则存储，由实时层执行。

实时防护层（毫秒级判断）→ 访问日志 → 行为分析层（秒级~分钟级）→ 规则存储 → 实时层读取执行

与实时层的分工：

层次判断依据响应延迟
实时层单条请求的特征毫秒级
行为分析层跨请求、跨时间窗口的累计模式秒级~分钟级

本文按价值从高到低介绍行为分析层的各分析维度。所有分析都建立在一个前提上：能把多条请求归属到同一个客户端——这就是客户端标识要解决的问题。

1. 客户端标识：行为分析的地基

行为分析的本质是"把同一个客户端的多次请求放在一起看"。标识选得越准，分析结论越可靠；标识被绕过，后续所有分析维度都会失效。

1.1 可选标识维度

客户端标识可以采用多种维度：业务 Cookie、WAF 生成的会话 Cookie、浏览器指纹、IP、UA、TLS 指纹、API 接口中的 Token，以及这些维度的组合。

标识方式准确性适用范围可被绕过
IP低粗略统计代理池轮换
IP + UA低粗略统计代理池 + UA 轮换
UA低辅助识别伪造、轮换，伪造门槛极低
TLS 指纹（JA3/JA4）中全场景更换 TLS 栈（成本高，但同工具不同实例指纹相同）
API Token高API 调用方多 Token 轮换
业务 Cookie（登录态）高已登录用户多账号轮换
WAF 会话 Cookie（服务端下发）高浏览器用户主动丢弃 Cookie
浏览器指纹 ID（客户端计算）高JS 执行环境伪造指纹（成本高）
组合方案最高全场景极难全面绕过

几个关键认知：

  • 没有任何单一维度是可靠的。IP 会被代理池绕过，Cookie 会被主动丢弃，指纹伪造虽有成本但并非不可能
  • 标识的价值在于提高绕过成本：攻击者绕过单一维度很容易，同时保持多个维度"干净"则成本陡增
  • 不同客户端类型适用不同维度：浏览器有 Cookie 和指纹可用；无鉴权的 API 客户端只有 IP + TLS 指纹；有鉴权的 API 调用方用 Token 最准

1.2 推荐组合流程

按"准确性从高到低"逐级回退选择标识：

请求进入
  │
  ├── 携带 API Token / 业务登录 Cookie → 用业务身份标识（最准确）
  │
  └── 无业务身份
        │
        ├── 有 WAF 会话 Cookie → 用 Session Token 标识
        │
        └── 无会话 Cookie
              │
              ├── 有浏览器指纹 → 用指纹 ID 标识
              │
              └── 无指纹 → 生成新会话标识下发，标记为新客户端

同时，IP 与 TLS 指纹作为辅助维度随主标识一同记录：主标识被丢弃/轮换时，可通过辅助维度做关联回溯（例如同一 TLS 指纹下出现大量不同会话标识，本身就是强可疑信号）。

2. 跨实体关联分析 ★★★

对抗分布式爬虫最有效的手段。分布式爬虫将请求分散到大量不同 IP/Session，单独看每个实体都不异常，但跨实体关联后暴露协同特征。

2.1 行为相似度聚类

不同 IP/Session 的请求序列、访问路径、请求间隔高度相似，说明是同一爬虫程序的多个实例。

  • 检测方法：对访问序列做向量化，计算不同 Session 间的余弦相似度，相似度超过阈值的归为同一爬虫集群
  • 处置：整个集群同时封禁

2.2 同一浏览器指纹登录多个账号

同一设备指纹在短时间内登录多个不同账号，说明是批量账号操作（薅羊毛、数据采集）。

2.3 /24 网段行为同步

同一 /24 网段内多个 IP 的访问路径、时序高度一致，说明是同一控制端调度的分布式节点（代理池）。

3. 蜜罐命中跨请求分析 ★★★

单次蜜罐命中由实时层处理（封禁当前会话并记录 IP + TLS 指纹），以下场景需要行为分析层介入：

3.1 同一 IP 短时间内多次命中蜜罐

  • 说明：大概率是代理池轮换，每次换会话但 IP 重复出现
  • 处置：触发 IP 封禁

3.2 IP + TLS 指纹组合多次命中

  • 说明：攻击者换了会话，但使用同一工具（TLS 指纹不变）
  • 处置：触发 IP + TLS 指纹组合封禁

4. 伪装行为识别 ★★☆

攻击者主动规避检测时产生的异常痕迹，均需跨请求累计观测。

可疑行为检测方式
频繁丢弃 Cookie统计同一 IP 在时间窗口内出现的不同会话标识数量，超过阈值即可疑
指纹缺失等待一段时间后确认该会话始终未回传浏览器指纹
IP 段聚集聚合 /24 网段内多个 IP 的行为，发现不同指纹但行为模式一致（代理池）
Session 行为异常统计该会话的历史请求序列，识别只访问 API 从不访问页面的异常模式

注："指纹与 UA 矛盾"这类单请求可判断的交叉验证归属实时层，不在行为分析层处理。

5. 错误率分布 ★★☆

爬虫在探测阶段会产生大量请求错误，是高置信度的扫描特征。

  • 短时间内同一 IP/Session 产生大量 404：路径扫描、目录枚举
  • 大量 403：权限探测
  • 爬虫在路径不存在时仍按规律继续请求；浏览器遇到 404 通常停止

检测指标：滑动窗口内 4xx 响应占比，超过阈值标记为扫描行为。

6. 访问行为模式分析 ★★☆

6.1 请求频率模式

  • 正常用户：页面请求间隔不规则，单次会话内有自然的波峰波谷
  • 机器人：固定间隔、极高频率、24 小时均匀分布

检测指标：单 IP / 单 Session 在滑动时间窗口内的请求计数、标准差、时间分布熵。

6.2 页面访问序列

  • 正常用户：首页 → 列表页 → 详情页 → 返回列表（有自然浏览路径）
  • 机器人：首页 → 详情页1 → 详情页2 → ... → 详情页1000（直奔目标数据页）

检测指标：会话内路径转移矩阵，与正常用户路径模型的 KL 散度。

6.3 静态资源请求行为

  • 正常浏览器：请求 HTML 后自动请求 CSS/JS/图片/字体
  • 机器人：只请求 HTML，不请求静态资源

检测指标：HTML 请求数 / 静态资源请求数比值，比值异常偏高即为可疑。

6.4 鼠标 / 键盘 / 触摸事件

需要客户端 JS 采集并回传，由行为分析层统一处理：

  • 正常用户：鼠标轨迹有加速度和曲线，点击位置有随机偏移
  • 机器人：无鼠标事件，或轨迹是直线 / 瞬移

7. 时间节律分析 ★★☆

7.1 跨天行为一致性

爬虫每天访问的路径、时序、参数高度重复；正常用户每天行为有随机性。

检测指标：连续多天的请求序列相似度。

7.2 深夜高频访问

正常用户有睡眠时段，凌晨访问量自然下降；爬虫 24 小时均匀或在低峰期集中访问（规避限流）。

7.3 会话持续时长

正常用户会话有自然终止（几分钟到数十分钟）；爬虫长时间不间断运行，单次会话可持续数小时。

8. 请求内容规律性 ★☆☆

8.1 参数遍历模式

请求参数呈规律性递增或枚举：id=1,2,3...、价格区间步长固定、分类 ID 顺序遍历等。

8.2 HTTP 方法分布

爬虫通常以 GET 为主；正常用户有 GET/POST/PUT 混合（表单提交、点赞、收藏等写操作）。

8.3 响应大小偏好

爬虫倾向于只消费有数据的大响应页面，跳过空列表页、错误页等小响应；正常用户响应大小分布更均匀。

9. 网络层分析 ★☆☆

9.1 IP 地理位置跳变

同一 Session 在短时间内从不同地理位置发起请求，说明在切换代理节点。

9.2 ASN 聚集

大量请求集中来自同一云服务商 ASN（如 AWS、阿里云），正常用户通常来自运营商 ASN。

9.3 IP 信誉库比对

与已知代理/VPN/Tor 出口节点数据库比对，命中即提高风险分。属于辅助信号，不单独触发封禁。

10. 业务行为特征 ★☆☆

与具体业务强耦合，需按站点定制，不可通用化。

业务场景爬虫特征
电商只浏览商品不加购、不下单（价格爬虫）
搜索搜索词规律性强、短时间覆盖大量关键词
内容平台账号只读取内容，无点赞/评论/关注等互动行为
账号体系注册后立即批量查询，无任何正常业务操作

11. IP 封禁决策

IP 是粗粒度标识，可能覆盖 NAT 后的大量正常用户，封禁需满足额外条件。

触发 IP 封禁的条件（满足任一）：

  ├── 同一 IP 在时间窗口内多次命中蜜罐          （行为分析层触发）
  ├── IP + TLS 指纹组合多次命中蜜罐或指纹库     （行为分析层触发）
  ├── IP 属于已知数据中心 / 云服务商 IP 段       （实时层静态规则）
  └── 频繁丢弃 Cookie（同 IP 大量不同会话标识）  （行为分析层触发）

不满足上述条件时，IP 只进入"高度观察"状态：后续来自该 IP 的请求风险评分基础值拉高，触发更严格检查，但不直接封禁——在误伤风险与防护强度之间取平衡。

结语

行为分析层的设计要点可以归纳为三条：

  1. 标识先行：客户端标识是所有分析的地基，单一维度不可靠，必须多维度组合并按准确性逐级回退
  2. 价值排序：跨实体关联与蜜罐分析产出高置信度结论，优先建设；业务特征最定制，最后落地
  3. 粗细分层：会话、指纹级标识可以果断封禁，IP 级封禁必须满足额外条件，避免误伤 NAT 后的正常用户

实时层决定了防护的"反应速度"，行为分析层决定了防护的"记忆深度"——两者协同，才能让防护系统既挡得住单点突袭，也看得穿慢速、分布式的长期渗透。
