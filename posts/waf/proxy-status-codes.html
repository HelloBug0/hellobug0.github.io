代理服务器的非标准 HTTP 状态码：CDN 与 WAF 的设计分野

引言

HTTP 状态码由 RFC 标准定义，取值范围为 100–599。但在 CDN、WAF、边缘加速等代理类产品的实际运行中，标准状态码往往不足以描述复杂的故障与安全场景，于是各厂商纷纷扩展出自己的非标准状态码。本文汇总了 Cloudflare、腾讯云、知道创宇、阿里云、长亭科技等主流厂商的自定义响应码使用情况，并从架构角度分析一个有意思的现象：为什么 CDN 类产品会使用大量非标准状态码，而纯 WAF 通常只用一个？

一、Cloudflare CDN

Cloudflare 是自定义 HTTP 响应码最丰富的厂商，分为两大类。

1. 5xx 系列自定义状态码（直接作为 HTTP 状态码返回）

这些状态码均不在 RFC 标准中定义，是 Cloudflare 独有的，用于描述边缘节点与源站之间的特定故障场景：

状态码含义触发场景
520Web Server Returns an Unknown Error源站返回了空的、未知的或意外的响应
521Web Server Is Down源站拒绝来自 Cloudflare 的连接
522Connection Timed OutCloudflare 与源站的 TCP 握手超时
523Origin Is Unreachable源站不可达（DNS 错误或源站宕机）
524A Timeout Occurred已建立 TCP 连接但源站响应超时
525SSL Handshake FailedCloudflare 与源站的 TLS 握手失败
526Invalid SSL Certificate源站的 TLS 证书无效
530Error 530伴随 1xxx 错误一起返回

依据：Cloudflare 官方文档 Cloudflare 5xx errors，最后更新于 2026-06-05。Wikipedia List of HTTP status codes 也收录了这些非标准码并标注为 Cloudflare 专有。

2. 1xxx 系列内部错误码（不直接作为 HTTP 状态码）

Cloudflare 的 1xxx 错误码是内部错误码，出现在响应体中，但 HTTP 状态行返回的是标准 4xx/5xx 码。官方文档明确说明：

"HTTP errors such as 409, 530, 403, and 429 are returned in the HTTP status header of a response, while 1XXX errors appear in the HTML body of the response."

依据：

  • Cloudflare 1xxx errors，最后更新于 2026-04-23
  • Cloudflare Error responses，最后更新于 2026-05-05

典型的映射关系：

1xxx 错误码含义实际 HTTP 状态码
1006-1008, 1106IP 被封禁/访问拒绝403
1015频率限制429
1001, 1016DNS 解析错误530
1012访问拒绝403
1200缓存连接限制429

1xxx 错误码在响应体中的承载方式

Cloudflare 通过 HTTP 内容协商（Content Negotiation） 机制，根据客户端请求中的 Accept 头选择响应格式，1xxx 错误码会嵌入到对应格式的响应体中：

客户端发送的 Accept 头返回格式1xxx 错误码的承载方式
text/htmlHTML 错误页面嵌入在 HTML 页面正文中（如页面显示 "Error 1015: You are being rate limited"）
*/*（浏览器默认值）HTML 错误页面同上
不发送 Accept 头HTML 错误页面同上
application/jsonJSON 结构化响应包含在 error_code 字段中（如 "error_code": 1015）
application/problem+jsonRFC 9457 格式 JSON包含在 error_code 字段中
text/markdownMarkdown 格式响应包含在 YAML frontmatter 的 error_code 字段中

关键设计要点：普通浏览器访问时（发送 Accept: */* 或 Accept: text/html），用户看到的是排版好的 HTML 错误页面，1xxx 错误码以可见文本形式呈现在页面上，用户体验与常规错误页面一致。仅当 API 客户端等程序化调用方发送 Accept: application/json 时，才会收到结构化 JSON 响应。

二、腾讯云

腾讯云旗下有三个产品涉及自定义状态码，且各自定义不同。

1. 腾讯云 WAF（独立产品，产品 ID 627）

腾讯云 WAF 独立产品默认拦截响应码为 403（标准码）。

依据：腾讯云 WAF 本地测试文档 Web 应用防火墙步骤2：本地测试——"返回 HTTP 拦截页面内容（如403 Forbidden状态码或WAF默认阻断页面）"。

腾讯云 WAF 独立产品未发现使用非标准状态码。

四、阿里云 WAF

拦截响应码

阿里云 WAF 默认使用标准 HTTP 状态码 405 (Method Not Allowed) 作为拦截响应码。虽然 405 是 RFC 标准中定义的（RFC 9110），但阿里云 WAF 将其用于安全拦截场景，这与其原始语义（HTTP 方法不被允许）并不一致。

  • 支持自定义响应码范围：200~600
  • 明确禁止使用：204、304、600、498
  • 滑块验证页面固定返回 200（不支持自定义）
  • 如果用户将响应码设为 204 或 304，WAF 会回退使用默认 405

依据：阿里云官方文档 如何设置自定义响应配置拦截或滑块响应页面——"默认拦截页面显示405错误码，提示'很抱歉，由于您访问的URL有可能对网站造成安全威胁，您的访问被阻断'"。

阿里云 WAF 产品本身未发现使用 RFC 标准之外的自定义响应码。但其自定义响应码中明确禁止使用 498，原因是 498 已被同属阿里云的边缘安全加速 ESA 产品的 WAF 组件内部占用（见下文）。

阿里云 ESA（边缘安全加速）中的非标准状态码

阿里云 WAF 产品本身未使用非标准码，但阿里云的边缘安全加速 ESA（CDN/边缘产品，内含 WAF 组件）使用了大量非标准状态码。文档明确指出："520~599 之间的状态码用于 ESA 对错误场景的细化，为防止混淆，建议您在业务中避免使用该范围内的状态码。"

五、长亭科技（雷池 SafeLine WAF）

拦截响应码

长亭雷池 WAF 使用标准 HTTP 状态码 403 (Forbidden) 作为默认拦截响应码。

  • 社区版拦截时固定返回 403，早期版本不支持自定义拦截响应内容
  • 后续版本增加了自定义拦截页面功能，但核心拦截状态码仍为 403
  • 上游源站返回错误码时，自定义拦截页面不再对上游错误码生效

依据：长亭雷池官方产品文档 雷池SafeLine 3.0 用户操作手册——明确标注"拦截页面状态码: 403"。

长亭雷池 WAF 未发现使用 RFC 标准之外的自定义响应码的记录。

分析：为什么 CDN 使用大量非标准状态码，而 WAF 通常只用一个？

WAF 的故障空间很小

WAF 的工作本质是一个安全决策引擎，只有两种结果：

  1. 放行 → 请求透传给源站，源站的响应码原样返回客户端（WAF 不参与响应码生成）
  2. 拦截 → WAF 自己生成一个响应，告诉客户端"你被拦了"

拦截只需要一个状态码就够了。不管是 SQL 注入、XSS 还是 CC 攻击，对客户端来说结果一样：请求被拒绝。所以一个 403 或 405 足矣。

CDN 的故障空间很大

CDN 是一个多层代理 + 缓存 + 协议终止 + 安全的复合系统，一条请求链路上有很多可能出错的环节：

客户端 → [TLS终止] → CDN边缘节点 → [缓存查找] → [回源DNS解析] → [回源TCP建连] → [回源TLS握手] → [回源HTTP请求] → 源站

每一个环节都可能独立失败，且失败原因各不相同：

环节可能的失败需要不同的状态码区分（以腾讯云 CDN 为例）
TLS 终止（面向客户端）握手失败、证书错误、连接超时562、563
缓存查找命中/未命中（不影响状态码）—
回源 DNS 解析域名解析失败531
回源 TCP 建连连接被拒、超时、RST532、533
回源 TLS 握手SSL 握手失败、证书过期、域名不匹配538、539、540
回源 HTTP 请求响应超时、数据接收超时537、567
平台层面过载保护、CC 封禁、限频524/614、509、514
安全拦截WAF 拦截、防盗刷566

核心区别

CDN 的非标准码多，不是因为它"想"定义这么多，而是因为它运营的是一套分布式基础设施，需要告诉用户"到底哪个环节出了问题"：

  • 运维人员看到 538 就知道是 SSL 握手问题，看到 531 就知道是 DNS 解析问题——不需要去翻日志
  • 监控系统可以根据不同状态码配置不同的告警策略和重试逻辑（DNS 错误可能需要切源站，SSL 错误需要更新证书）

WAF 的非标准码少，是因为它只需要回答一个问题：拦还是不拦。拦了就返回一个统一的状态码，至于为什么拦（SQL 注入还是 XSS），那是日志和告警系统的事，不需要体现在 HTTP 状态码里。

规律总结

从上述各厂商的数据中可以看到一个规律：越接近"基础设施运营"的产品，自定义非标准码越多；越接近"纯安全决策"的产品，自定义非标准码越少。

产品类型非标准码数量原因
腾讯云 CDN（纯 CDN）18 个全链路故障细化
阿里云 ESA（CDN+WAF）17 个CDN 基础设施 + 边缘函数
腾讯云 EdgeOne（CDN+WAF）8 个CDN 基础设施
Cloudflare（CDN+WAF）8 个（5xx 系列）源站连接故障细化
知道创宇（WAF+抗D）4 个安全拦截为主
阿里云 WAF（纯 WAF）0 个纯安全决策
腾讯云 WAF（纯 WAF）0 个纯安全决策
长亭雷池（纯 WAF）0 个纯安全决策

结论：非标准码的数量与产品承担的"基础设施复杂度"正相关，与"安全决策"本身无关。
